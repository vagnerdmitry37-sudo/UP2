# Persistence

- `Migrations/` is generated by `dotnet ef` (commands in root CLAUDE.md). Never edit migration files or `AppDbContextModelSnapshot.cs` by hand.
- Bad migration not yet committed/applied → `dotnet ef migrations remove`, fix the model, regenerate. Already committed → add a new migration on top.
- Schema changes go in the entity + its `IEntityTypeConfiguration` (e.g. `Auth/RefreshTokenConfiguration.cs`); `AppDbContext` picks them up via `ApplyConfigurationsFromAssembly`.
